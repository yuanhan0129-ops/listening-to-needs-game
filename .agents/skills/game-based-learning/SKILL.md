# 遊戲式學習設計與實作

協助使用者把學習內容做成可玩的數位遊戲或原型。使用者要求實作時，完成專案裡的遊戲；使用者只要構想或規格時，先交付相應的設計成果，不要自行擴大工作範圍。

## 工作流程

1. **先了解專案與任務。** 閱讀適用的 `AGENTS.md`，檢視現有程式、框架、入口、介面慣例及相關說明，沿用專案已有的技術與風格。確認使用者、學科主題、學習者程度、使用情境、裝置和時長。已有資訊就直接採用；缺少但不影響方向時，明確寫出合理假設繼續。只有會改變玩法或交付平台的重要缺項才簡短詢問。

2. **把學習目標變成遊戲裡的行動。** 分清「遊戲目標」（玩家在遊戲中要完成什麼）與「學習目標」（希望玩家學會什麼）。將學習目標寫成可觀察的表現，並建立這條對應關係：

   | 學習目標 | 玩家要做的行動或決策 | 遊戲規則／狀態如何回應 | 可觀察的學習證據 |
   |---|---|---|---|

   若玩家不必運用目標知識也能輕易拿高分或通關，調整玩法、規則、回饋或計分，使目標能力在遊戲中真正派上用場。

3. **依學習行動選玩法。** 保留使用者指定的形式；若未指定，依目標挑選最簡單合適的形式。辨認模擬、遊戲和遊戲化的差異：模擬讓玩家改變條件、觀察模型結果；遊戲另有目標、規則、決策或進展；遊戲化是在原有非遊戲活動中加入點數、徽章等元素。這些形式可以組合，勿把增加獎勵當成已完成遊戲設計。

4. **設計一個清楚、可重複的核心循環。** 以「看見狀態或資訊 → 作出選擇 → 規則改變局面 → 看懂結果 → 再試或進階」串起遊玩。當學習目標涉及比較或策略時，讓不同選擇有可理解的代價與後果，並提供作判斷所需的資訊。逐步增加需要處理的條件；必要時提供提示、範例或可重試機會，再依進度減少支援。

5. **讓回饋說明原因。** 除了對錯、分數或動畫，盡可能指出玩家的行動如何造成結果、哪些資料支持此結果，以及下一步能如何修正。計分與獎勵應鼓勵目標行為，避免鼓勵猜答案、盲目點擊、搶快或其他可繞過學習的策略。若目標只是辨認或回想事實，問答形式可以合適；仍要讓成功標準和學習目標一致。

6. **製作符合專案的可玩成果。** 實作使用者要求的核心體驗，優先完成清楚的目標、必要說明、玩家行動、狀態變化、結果回饋和下一步。介面用語符合對象程度；重要資訊不要只靠顏色或聲音傳達，並盡量讓操作、文字與節奏容易理解。若用於課堂，視任務需要提供遊玩前的背景／規則、遊玩中的觀察重點，以及遊玩後的討論或新情境練習。

7. **用對證據描述學習。** 區分參與（例如願意重試）、當下學習、延後保留，以及把理解用於新條件的遷移。遊戲分數、完成時間、點擊或遊玩紀錄只能作為線索，不能單獨證明理解或因果成效。評量方式要對應目標：例如要求解釋、操作、根據資料作選擇，或在不同情境中重新應用。沒有實際資料時，不宣稱遊戲已證明有效。

## 完成檢查

- 遊戲目標與學習目標都清楚，且彼此相關。
- 每項主要學習目標都對應到玩家行動、遊戲結果和可觀察證據。
- 規則、資訊和回饋讓玩家能理解選擇與後果的關係。
- 得分或通關方式不會獎勵與學習目標相反的捷徑。
- 遊戲可在本專案的技術架構中使用；回報實際完成的範圍與尚未處理的部分。

遵守使用者和專案既有指示。除非使用者要求測試或驗證，否則不要新增或執行測試；若未執行，清楚說明尚未驗證的項目。

## 設計依據

本 Skill 參考使用者提供的《數位遊戲式學習：概念、設計與教學應用》，尤其是目標、玩家行動與證據的連結、狀態／行動／規則與核心循環、能解釋原因的回饋、循序挑戰與暫時支援，以及分開評估參與、學習、保留和遷移。文件中的供水決策與校園消息查證是示例；依使用者的主題重新設計，不要把示例硬套到每個遊戲。
