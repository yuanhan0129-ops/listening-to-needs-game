# 《聽見需要》遊戲企劃書

## 1. 遊戲概念

《聽見需要》是一款給成人遊玩的短篇互動敘事遊戲。玩家閱讀虛構角色的日常對話，從言語線索推敲可能的情緒與需要，再選擇一種回應，看看對話如何發展。

遊戲練習的是情緒辨識與溝通，不提供診斷或治療，也不要求玩家揭露自己的經歷。每種選擇都會帶出不同但有效的對話結果，不設分數、正解或好壞結局。故事後的自我反思完全自願、可以跳過，而且不輸入、不儲存。

## 2. 目標玩家與學習目標

- **目標玩家：** 成人。
- **核心學習目標：** 練習辨認並說出一個人的可能情緒與需要。
- **延伸練習：** 嘗試不同的傾聽、提問、提出小建議或提供選擇等回應方式，觀察它們如何影響對話。
- **遊戲情境：** 工作、人際、休息等日常生活故事；語氣寫實、成熟而柔和。

| 學習目標 | 玩家行動 | 遊戲回饋 | 可觀察的練習證據 |
| --- | --- | --- | --- |
| 從對話中注意情緒線索 | 閱讀角色的話，選擇一種可能的情緒 | 選項被標示，玩家可在繼續前調整 | 玩家選出並說明一種暫時的情緒理解 |
| 推敲情緒背後的需要 | 選擇一項可能的需要 | 遊戲明確提醒沒有唯一標準答案 | 玩家把情緒與一項可能需要連結起來 |
| 練習回應方式 | 選擇一種回應並閱讀分支對話 | 角色依不同回應作出不同反應，故事繼續 | 玩家探索不同對話路徑並比較角色反應 |
| 自願連結到自身經驗 | 閱讀可略過的反思卡，在心裡思考即可 | 無輸入欄、無儲存、可直接完成 | 不蒐集個人反思內容 |

## 3. 核心遊戲循環

1. 閱讀一段日常對話線索。
2. 選擇角色可能的情緒與需要；玩家可以把它們當作暫時推測，而非替角色定論。
3. 選擇一種回應方式。
4. 閱讀對應的角色反應與對話發展。
5. 自願閱讀反思卡，或略過。
6. 回到結尾探索另一種有效回應。

遊戲以故事完成與分支探索作為回饋，不評分情緒推測，也不把任何回應標示成正確答案。

## 4. MVP 範圍

### 第一篇故事：「很累，卻停不下來」

- 虛構角色：予安，一位同事。
- 日常處境：疲累但難以停止工作，擔心漏掉事情或讓別人失望。
- 情緒與需要選項：各四項，均以「可能」呈現。
- 回應方式：反映線索並邀請多說、提出一個小休息建議、提供選擇。
- 分支結果：三種不同的角色反應與故事走向，沒有失敗或壞結局。
- 反思卡：邀請玩家在心裡想想此刻的感受與需要；可跳過，不需輸入或儲存。
- 平台：桌面與手機瀏覽器；支援滑鼠、觸控及鍵盤操作。
- 入口：載入後直接進入故事，不另設首頁。

## 5. 視覺與素材方向

- 簡約扁平，以對話卡片和柔和色塊呈現。
- 使用暖白、鼠尾草綠、灰藍與柔和陶土色，避免強烈、競爭性或警示式的視覺語言。
- MVP 介面以 Phaser 幾何圖形繪製，搭配原創編輯插畫肖像、細緻陰影與分段進度；字體採用系統字體，讓桌機與手機維持清晰一致的閱讀層級。
- Kenney UI Pack 已從 [Kenney 官方頁面](https://kenney.nl/assets/ui-pack) 取得並確認包內授權資訊為 CC0。檢視後因鮮明配色、立體邊框與陰影不符合本作方向，暫不載入遊戲；素材與來源記錄保留於專案，供之後挑選個別素材時參考。

## 6. 實作階段

### 階段 0：素材挑選（已完成）

1. 確認遊戲視覺方向與使用裝置。
2. 取得並檢視 Kenney UI Pack 的官方預覽、內容與授權。
3. 比較素材風格和遊戲方向；記錄採用或不採用的理由及來源。
4. 為 MVP 選用 Phaser 繪製的介面與專案自製 SVG 肖像。

### 階段 1：MVP（已建立，待實際遊玩後迭代）

1. 建立直接進入故事的 Phaser 場景與響應式畫面。
2. 完成第一篇日常故事、情緒／需要推敲、回應選擇與三種有效分支。
3. 加入可略過且不儲存資料的反思卡，以及完成後重看其他分支的流程。
4. 提供鍵盤、滑鼠與觸控操作，讓同一個遊戲入口適用桌面及手機瀏覽器。

### 階段 2：互動與介面修整

1. 以桌面和常見手機尺寸實際遊玩，調整文字換行、卡片間距、按鈕大小與窄螢幕版面。
2. 檢視鍵盤焦點、文字對比、選取狀態和操作提示，讓選項不只靠顏色區分。
3. 根據遊玩觀察修正對話節奏與選項文字，保持「推測而非判定」的語氣。

   **已完成首輪：** 更新予安的情境肖像，統一暖紙色、森林綠與陶土色，為對話加入角色資訊、分段進度、柔和陰影與清楚的互動狀態；已檢視桌面預覽及 390 × 844 手機預覽。

### 階段 3：擴充故事內容

1. 沿用同一套流程新增人際與休息等日常情境。
2. 每篇故事先定義可觀察的練習目標，再撰寫線索、情緒／需要選項、回應方式與不同有效結果。
3. 確認分支不以羞辱、懲罰或分數評斷玩家，也不暗示玩家能替角色診斷。

### 階段 4：整合與內容品質

1. 統一故事資料格式、介面用語與視覺規範，整理新增素材的來源及授權紀錄。
2. 逐篇確認反思仍可跳過、個人輸入不被要求，且遊戲不宣稱能治療創傷。
3. 依實際遊玩回饋決定是否需要後續內容或功能；任何個人反思資料若要儲存，需另行重新定義需求與告知方式。

## 7. 專案實作位置

- `src/scenes/GameScene.js`：Phaser 畫面、互動與遊戲流程。
- `src/data/scenarios.js`：故事、選項與分支內容。
- `src/game/config.js`：Phaser 啟動與縮放設定。
- `src/styles.css`、`index.html`：全螢幕遊戲入口與頁面樣式。
- `public/assets/images/characters/`：遊戲使用的角色圖像，包含原創的 `yu-an-portrait.png`。
- `assets/source/kenney/`：Kenney 原始素材、清單與素材挑選紀錄。

## 8. 設計界線

- 遊戲提供的是情緒辨識與對話練習，不是心理治療、診斷或危機處置工具。
- 玩家對角色的情緒與需要只作為探索假設，遊戲不宣稱能判定他人的真實內在狀態。
- 玩家可以略過反思；遊戲不要求分享創傷或私人經驗，也不儲存反思內容。
- 各種回應路徑呈現不同可能性，不以輸贏、道德評價或「正確溝通」分數排序。
